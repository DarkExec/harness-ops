# Efficiency Pass

Review the immediately preceding Harness pass and improve how future Harness passes produce durable
ordinary-execution gains.

## Start here

1. Run `toolburn pass previous`. Treat its content-free receipt as a selector, not a score.
2. If present, read the target's `docs/passes/efficiency/AGENTS.md` only as its local ownership,
   validation, and delivery overlay.
3. Inspect raw evidence only for the largest plausible Harness-pass tax. Do not reopen the original
   product job. Use `DOCTRINE.md` or `PLAYBOOK.md` only for a named unresolved question.

## Working loop

1. Confirm the Harness outcome, intervention or no-op, proof, delivery, and failed or repeated work.
2. Locate the earliest owner encountered before the selected tax: ToolBurn for receipt collection or
   classification; this shared pass bundle for cross-project method; the target overlay or target
   path for local ownership, validation, delivery, or proof.
3. Apply at most one small change whose credible repeated benefit exceeds creation and carrying
   cost. Prefer repair, deletion, consolidation, or a better default over another instruction.
4. Prove the mechanism and delivery identity. A later comparable receipt may be compared with
   `toolburn compare`; factual deltas are not a rating or proof of causality.
5. Return a measured no-op when the path already prevents the tax or no intervention clears the
   worth gate. Do not stack recursive optimization while an intervention awaits exposure.

## Qualification

Independent evaluation—not ToolBurn or the pass being evaluated—decides `retain`, `revise`, or
`remove` from comparable exposed work. Preserve outcome, authority, proof, portability, and recovery
even when a cheaper-looking path would improve a metric.
