# Efficiency Pass

Review the immediately preceding Harness pass and improve how future Harness passes turn completed ordinary work into durable execution gains.

## Start here

- Use the target's compact pass telemetry as the initial receipt, then inspect only the evidence needed to resolve the largest plausible Harness-pass tax.
- Route to `DOCTRINE.md` for an unresolved placement or qualification decision and `PLAYBOOK.md` for an unresolved operating step.

## Working loop

1. Confirm the Harness outcome, intervention, execution cost, and any failed or repeated work.
2. Select the most consequential avoidable tax that is likely to recur in Harness execution.
3. Locate the earliest existing Harness prompt, map, tool, default, or validation owner encountered before that tax.
4. Apply the smallest coherent improvement whose expected repeated benefit exceeds its creation and carrying cost.
5. Run the owner's focused proof, deliver through the target workflow, and report the evidence, encounter point, expected benefit, and uncertainty.

An evidence-backed no-op is the right result when the current Harness path already prevents the tax or no intervention clears the worth gate. Git history carries delivery evidence; a separate artifact is useful only when it is itself the automatically encountered execution owner.

## Qualification

Later comparable Harness passes reveal whether the intervention should be retained, revised, or removed. Treat delivery as a hypothesis made available for natural exposure, not as proof of realized efficiency.
