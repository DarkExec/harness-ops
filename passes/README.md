# Harness Ops Passes

These are the released default execution maps for Harness Ops. They travel with the doctrine so a
pass prompt can use one stable installed route without copying a scaffold into every target.

## Prompts

Harness:

```text
After reading /srv/harness-ops.md, follow /srv/harness-ops/passes/harness/AGENTS.md. Review all ordinary turns since the previous Harness pass and make the single highest-leverage durable improvement to comparable future ordinary execution. Prefer a small earliest-owner change encountered before the observed cost. Return a concise no-op only when evidence shows the existing path already prevents the cost or no credible small intervention exists.
```

Efficiency:

```text
Review the immediately preceding Harness pass following /srv/harness-ops/passes/efficiency/AGENTS.md.
```

The pass maps begin with a content-free ToolBurn receipt and progressively disclose raw trajectory
evidence only for one selected cost. ToolBurn reports facts; an independent evaluator owns ratings
and causal conclusions.

## Target overlays

A target may add `docs/passes/harness/AGENTS.md` or `docs/passes/efficiency/AGENTS.md` when it needs
local owner, validation, delivery, or proof routes. Keep overlays short. Shared selection,
worth-gating, anti-overfitting, and qualification rules remain here.

Validate the complete release from the Harness Ops root:

```bash
./scripts/validate.sh
```
